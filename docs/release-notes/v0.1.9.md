## 新增与改进

- 在这台 Mac 上自己构建时，可以选择用一张本机自签名证书签名，更新之后签名身份保持不变；公开下载的安装包仍然是 ad-hoc 签名，这个选项只在本机构建时显式开启。
- 本机签名的包把证书的 SHA-1 和 SHA-256 写进包信息；更新时先核对官方摘要，再用本机身份重新签名，然后从包里读出证书、包标识和指定要求逐项比对，全部对上才算安装成功。
- 包内签名策略缺失、读不出来，或证书换过但名字相同，都直接拒绝安装，不会悄悄退回 ad-hoc 路径。
- 签名相关的外部命令都带超时，超时会终止并说明原因，不会一直卡住。
- 监听启动失败时区分「没有授权」和「有授权但监听创建不起来」两种情况；诊断文件只记状态，不记任何输入内容。

## What's New & Improved

- A build made on your own Mac can be signed with a local self-signed certificate, so the signing identity stays the same across updates; public downloads stay ad-hoc signed, and this only turns on for local builds that set the two variables.
- A locally signed build records the certificate's SHA-1 and SHA-256 in the bundle; an update checks the official digest first, re-signs with the local identity, then reads the certificate, bundle identifier and designated requirement back and compares each one before installing.
- A missing or unreadable signing policy in the bundle, or a different certificate under the same name, refuses the install instead of quietly falling back to ad-hoc.
- External commands used for signing run with a timeout: on timeout they are stopped with a stated reason instead of hanging.
- A listener that fails to start now reports "not authorized" and "authorized but could not start" separately, and the diagnostics file records states only, never any input.
